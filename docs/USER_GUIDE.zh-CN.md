# Sprite Intelligence Workbench 使用手册

本文档面向需要把 AI 生成图片转换成游戏角色帧、Sprite Sheet 或整套动画素材的使用者。README 负责项目简介和安装，本手册重点说明实际操作、参数选择、人工修复、批处理与问题排查。

## 1. 开始之前

### 支持的素材

- PNG、JPG、JPEG、WEBP、BMP
- 单张角色图
- 一张图片中包含多帧角色的 Sprite Sheet
- 一个文件夹中包含多张动作图或逐帧图片的动画组
- 白底、纯色底、透明底以及常见绿幕/蓝幕图片

### 推荐的源图条件

- 相邻角色之间保留可见间距
- 不同帧不要大面积重叠
- 背景颜色尽量稳定
- 已知帧数时保留这个信息
- 同一动画组使用有序文件名，例如 `frame_001.png`、`frame_002.png`

如果两个角色在源图中已经粘连成同一个轮廓，系统无法凭空恢复被遮挡的信息。这类情况应重新生成源图，或在生成阶段改为逐帧输出。

## 2. 启动与关闭

双击项目根目录的 `start_gui.bat`，浏览器会打开：

```text
http://127.0.0.1:7865
```

也可以在 PowerShell 中启动：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start_gui.ps1
```

指定端口或代理：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start_gui.ps1 `
  -Port 7865 `
  -Proxy http://127.0.0.1:7897
```

关闭浏览器标签页不会删除任何任务。需要完全停止服务时，可在任务管理器中结束对应的 Python/Uvicorn 进程。

## 3. 界面布局

GUI 分为三个主要区域：

1. **左侧素材库**：导入素材、查看动画组、AI 处理记录和处理历史。
2. **中央画布**：查看原图、初抠、精修、蒙版和实例归属，并执行点选或圈选修正。
3. **右侧控制栏**：设置分析参数、查看识别结果、运行分析和执行导出。

桌面宽度足够时，可以拖动两条区域边界无级调整宽度；双击边界恢复默认布局。边界获得焦点后，方向键每次调整 8 px，按住 Shift 时每次调整 24 px。

常用快捷键：

| 快捷键 | 作用 |
| --- | --- |
| `Ctrl + Enter` | 运行当前图片的智能分析 |
| `←` / `→` | 在当前动画组中切换上一张/下一张 |
| `Enter` / `Space` | 打开键盘聚焦的素材或历史记录 |

输入框、下拉框、弹窗、局部修正或批处理进行中时，方向键不会切换素材。

## 4. 导入素材

### 导入单张图片

点击“导入素材”并选择一张图片。图片会被复制到 `input/`，随后在中央画布打开。

也可以把图片直接拖入左侧导入区或中央画布。

### 导入多张图片或整个文件夹

使用同一个“导入素材”入口选择多张图片或文件夹，程序会自动判断导入模式。确认窗口会显示：

- 有效图片数量
- 子目录数量
- 总大小
- 被跳过的非图片文件
- 动画组名称

确认后，目录结构会保存在：

```text
input/<动画组名称>/...
```

素材、AI 处理记录和处理历史都会使用这个动画组名称进行聚合。点击组标题可以折叠或展开，折叠状态会保存在当前浏览器中。

### 导入顺序

动画组内部按文件名自然排序。推荐补零命名：

```text
frame_001.png
frame_002.png
frame_010.png
```

不要使用 `frame_1.png、frame_10.png、frame_2.png` 这种容易产生顺序歧义的命名方式。

## 5. 分析参数

大多数素材可以保持默认值。优先调整“预期帧数”，不要一开始就同时修改所有参数。

### 5.1 布局提示

| 参数 | 默认值 | 使用建议 |
| --- | ---: | --- |
| 预期帧数 | `0` | 已知总帧数时填写；这是最有价值的提示。`0` 表示自动判断。 |
| 行 | `0` | 只有明确知道排版行数时填写。 |
| 列 | `0` | 只有明确知道排版列数时填写。 |

行和列只是视觉推断提示，不是强制裁切边界。

### 5.2 背景处理

| 模式 | 适用情况 |
| --- | --- |
| 自动判断 | 推荐默认值；系统在纯色连通背景与 AI 抠图之间选择。 |
| AI 抠图 | 复杂背景、渐变背景、摄影或背景不连通时使用。 |
| 连通色背景 | 背景颜色非常统一，并且与角色有明显色差时使用。 |

### 5.3 背景模型

| 模型 | 适用情况 |
| --- | --- |
| ISNet Anime / 插画 | 默认；动漫角色、卡通、游戏立绘、Q 版角色。 |
| BiRefNet / 通用 | 复杂物体、通用图片或 ISNet 结果不理想时尝试。 |
| U²-Net / 兼容 | 兼容性选择；用于对比或旧工作流。 |

第一次切换到未缓存的模型时可能需要下载模型文件。

### 5.4 智能绿幕净化

智能绿幕默认开启，但只在检测到均匀、高饱和的绿色或蓝色画布时工作。

| 强度 | 使用建议 |
| --- | --- |
| 保守 | 角色自身包含较多绿色/蓝色，优先避免误删。 |
| 标准 | 默认推荐，兼顾封闭孔洞和边缘绿溢。 |
| 强力 | 背景残留明显、绿边严重时使用。 |

角色本身与绿幕颜色非常接近，并且缺乏轮廓或语义证据时，应关闭智能绿幕，改用保守精修或局部修正。

### 5.5 组件灵敏度

组件灵敏度影响系统把多少独立物体视为候选组件：

- 调高：更容易保留小型武器、碎片、纸张、运动线和特效，也更容易把噪点当作组件。
- 调低：减少零碎噪声，但可能漏掉真正的分离特效。

建议先保持 `50`。只有在明显漏掉分离组件或产生大量噪声组件时再调整。

### 5.6 自动归属置信线

置信线决定哪些组件需要进入人工核对：

- 调高：更多组件被标记为待核对，审核更严格。
- 调低：减少待核对数量，但自动归属错误更不容易被发现。

它主要控制审核门槛，不应被当作背景清理参数。默认 `42` 适合一般素材。

## 6. 蒙版精修

### 自动精修强度

| 强度 | 使用建议 |
| --- | --- |
| 关闭 | 完整保留初抠结果，用于排查精修是否误删。 |
| 保守 | 默认；优先保护角色，清理明显背景孔洞和边缘污染。 |
| 标准 | 保守模式仍有明显背景残留时使用。 |
| 强力 | 背景残留严重时使用，必须对比初抠结果检查误删。 |

### 背景颜色容差

容差越大，允许被识别为背景的颜色范围越宽。

- 出现白边、浅色残留：小幅提高。
- 角色浅色皮肤、头发或服装被误删：降低。
- 不要一次拉到最大；每次少量调整后点击“重新精修当前蒙版”。

### 边缘羽化宽度

用于软化透明边缘：

- 过低：边缘可能出现锯齿或硬切。
- 过高：轮廓发虚、细节变薄。
- 一般保持 `2–4`，默认 `3`。

“重新精修当前蒙版”会从保留的初抠结果重建蒙版，不会重新运行实例分割模型。

## 7. 查看分析结果

中央画布顶部包含以下视图：

| 视图 | 用途 |
| --- | --- |
| 原图 | 查看未经处理的输入。 |
| 初抠 | 查看背景移除器的初始 Alpha，用于判断误删来自初抠还是后续精修。 |
| 精修 | 查看当前最终蒙版结果，也是点选和圈选修正的操作视图。 |
| 蒙版 | 检查 Alpha 是否存在孔洞、锯齿或残留。 |
| 实例归属 | 查看帧边框、组件编号、归属和低置信提示。 |

红色边缘或“建议核对”表示模型置信度低，不代表一定错误。

## 8. 人工修正

### 8.1 清除背景

适合一个颜色连通的残留背景区域，例如头发间的白色孔洞。

1. 切换到“精修”视图。
2. 点击“清除背景”。
3. 点击残留背景内部。
4. 系统只更新与点击颜色相近且连通的区域。

### 8.2 恢复前景

适合恢复被误删的小块、单色角色细节。

1. 切换到“精修”视图。
2. 点击“恢复前景”。
3. 点击需要恢复的区域。

如果误删区域包含多种颜色，应使用“圈选恢复”。

### 8.3 圈选恢复

从保留的初抠结果恢复圈内内容，适用于强力精修误删头发、发饰、翅膀或服装。

1. 点击“圈选恢复”。
2. 按住鼠标沿目标外缘绘制闭合区域。
3. 松开后检查多边形范围。
4. 点击“应用恢复”。

圈外 Alpha 不会改变。圈选应尽量贴近目标，避免把附近背景一起恢复。

### 8.4 圈选精修

重新处理圈内的背景残留，但不会把整个圈选区域直接删除。

1. 点击“圈选精修”。
2. 选择轻度、标准、强力或极强。
3. 圈住需要重新抠图的局部。
4. 点击应用。

系统会结合整图绿幕颜色、局部颜色、平坦度和语义前景证据，只降低具有背景证据的像素 Alpha。建议从“标准”开始。

### 8.5 修正实例归属

1. 打开“实例归属”。
2. 点击画布上的彩色组件或右侧待核对编号。
3. 选择 `F1、F2……` 指定所属帧。
4. 与任何帧无关的噪声可以选择“忽略”。

帧主体锚点不能被移动或忽略，避免破坏整个布局。

## 9. 动画组批处理

打开动画组中的任一图片后，右侧底部会显示：

- 运行智能分析
- 整组分析
- 导出整组
- 已导出时的 `result` 预览入口

### 整组分析

- 当前布局提示、背景策略、模型和精修参数会应用到组内所有图片。
- 已有任务的图片可以跳过，适合中断后续跑。
- 可以选择完成当前图片后停止。
- 分析完成后，使用画布两侧按钮或方向键查看每张图片的处理结果。

### 整组导出

- 默认跳过仍有待核对组件的任务。
- 确认结果可接受时，可以选择包含待核对任务。
- 自定义目标目录会保留源素材的相对目录，避免同名帧互相覆盖。
- `result` 文件夹保存集中预览，便于快速检查整组结果。

## 10. 导出内容

| 类型 | 内容 | 推荐用途 |
| --- | --- | --- |
| 统一尺寸帧 `aligned` | 相同画布、底部居中 | 角色动画、Godot/Unity 序列帧，默认推荐 |
| 紧凑透明帧 `trimmed` | 每帧裁到最小透明边界 | UI 图标、需要自行定义锚点的资源 |
| Sprite Sheet `sheet` | 把 aligned 帧重新排成图集 | 引擎图集导入、集中预览 |
| 透明蒙版 `masks` | 每帧 Alpha 蒙版 | 二次合成、着色器或人工修图 |
| Manifest `manifest` | JSON 布局、边界框、锚点和组件信息 | 自动化管线、游戏导入工具 |
| 完整处理包 `all` | 上述全部内容 | 归档、调试或下游流程不确定时 |

同一张源图片会记住自己的导出目录与内容类型。动画组另外记住整组设置，不会错误复用其他素材最近一次的路径。

## 11. 素材库、AI 记录与处理历史

- **素材**：显示 `input/` 中的可处理文件，按动画组聚合。
- **AI处理记录**：显示由 AI CLI 创建或导出的 `ai` 标签任务。
- **处理历史**：显示所有分析任务。

动画组中的 AI 任务会作为一组显示，不会逐张散落。单图任务进入“单张 AI 记录”或“单张处理记录”。

点击左侧“管理”可以多选记录并移入回收站：

- 删除素材时默认同时整理关联任务。
- 导出成品不会被删除。
- 被移除内容保存在 `workspace/trash/<时间批次>/`，属于可恢复操作。
- 不要直接删除 `workspace/jobs` 中的单个文件，否则任务可能无法恢复。

## 12. CLI 使用

客户端位置：

```text
skills/ai-sprite-workflow/scripts/sprite_workflow_client.py
```

以下示例假设当前目录是项目根目录。

### 单图分析并导出

```powershell
.\.venv\Scripts\python.exe `
  .\skills\ai-sprite-workflow\scripts\sprite_workflow_client.py `
  process .\input\hero.png `
  --expected-frames 6 `
  --output F:\game-assets\hero\attack
```

仅分析、不导出：

```powershell
.\.venv\Scripts\python.exe .\skills\ai-sprite-workflow\scripts\sprite_workflow_client.py `
  process .\input\hero.png --analyze-only
```

处理项目外图片时必须明确允许导入：

```powershell
.\.venv\Scripts\python.exe .\skills\ai-sprite-workflow\scripts\sprite_workflow_client.py `
  process F:\generated\hero.png --import-external
```

### 文件夹工作流

```powershell
# 注册完整动画文件夹
.\.venv\Scripts\python.exe .\skills\ai-sprite-workflow\scripts\sprite_workflow_client.py `
  import-folder F:\generated\hero-walk --collection hero-walk

# 处理整个动画组；已经处理过的图片跳过
.\.venv\Scripts\python.exe .\skills\ai-sprite-workflow\scripts\sprite_workflow_client.py `
  process-folder .\input\hero-walk --skip-existing --output F:\game-assets\hero

# 导出动画组最近保存的结果
.\.venv\Scripts\python.exe .\skills\ai-sprite-workflow\scripts\sprite_workflow_client.py `
  export-folder hero-walk --output F:\game-assets\hero
```

### 选择导出内容

下面示例中的 `...` 表示共同前缀 `.\.venv\Scripts\python.exe .\skills\ai-sprite-workflow\scripts\sprite_workflow_client.py`。

```powershell
# 默认 aligned
... process .\input\hero.png --output F:\game-assets\hero

# 只导出 Sprite Sheet
... process .\input\hero.png --artifact sheet

# 组合导出
... export <job-id> --artifact aligned --artifact manifest

# 完整处理包
... export <job-id> --all
```

CLI JSON 中的 `delivery_dir` 是调用方最终应该使用的目标目录；`output_dir` 是项目内部标准输出缓存。

### 检查与修正任务

```powershell
... inspect <job-id>
... refine <job-id> --mode balanced --tolerance 18 --matte-width 3
... mask-point <job-id> 420 180 background
... restore-region <job-id> "365,35;495,35;525,150;345,150" --feather 4
... refine-region <job-id> "365,35;495,35;525,150;345,150" --strength strong
... assign <job-id> <component-id> <frame-id>
```

`frame-id=0` 表示忽略非主体组件。

## 13. 在 AI 对话中调用

项目内置 `$ai-sprite-workflow` Skill。可以直接描述目标：

```text
$ai-sprite-workflow 处理 F:\game-tool\input\hero-attack.png，预期 6 帧，
导出 aligned 到 F:\godot-game\assets\hero\attack，告诉我哪些组件仍需人工核对。
```

处理文件夹：

```text
$ai-sprite-workflow 导入并处理 F:\generated\hero-walk，作为 hero-walk 动画组，
跳过已有任务，导出到 F:\godot-game\assets\hero。
```

AI 返回结果时应重点查看：

- `delivery_dir`：最终交付目录
- `review_count`：需要人工核对的组件数量
- `overlay_path`：实例归属叠加图
- `initial_cutout_path`：初抠结果
- `refined_cutout_path`：精修结果

## 14. 常见问题

### 边缘有毛刺、白边或背景色残留

1. 保持自动精修为“保守”。
2. 小幅提高背景颜色容差。
3. 将边缘羽化调整到 `2–4`。
4. 仍有局部残留时使用“圈选精修”，不要直接使用全局强力。

### 绿幕残留在翅膀、尾巴或身体内部

确认智能绿幕已开启，先使用“标准”，重度绿溢再切换“强力”。封闭孔洞不需要与画布边缘连通也能被清理。

### 角色本身的绿色部分被删除

切换智能绿幕为“保守”或关闭，然后从初抠重新精修。已经误删的局部使用“圈选恢复”。

### 强力精修删除了头发或服装

切换到“初抠”确认该部分仍存在，然后使用“圈选恢复”。不要连续使用大量“恢复前景”点击处理多颜色区域。

### 圈选精修把整个尾巴删除

确保使用的是最新版本。当前局部精修只会写回有背景证据的 Alpha 降低结果，不应把整个圈选区域当作橡皮擦。先用“标准”强度，并缩小圈选范围。

### 帧数识别错误

优先填写准确的“预期帧数”。只有明确知道排版时才补充行列。检查相邻角色是否已经粘连，或是否存在面积很大的标题、装饰物被当作主体。

### 分离武器或特效归错帧

打开“实例归属”，点击对应组件并手动指定到正确的 `F` 编号。不要通过提高背景容差解决归属问题。

### 文件夹下一张显示原图而不是分析结果

确保整组分析已经完成。程序会按源路径自动加载该图片最近一次任务；如果该图片尚未分析，会显示原图。可在右侧查看“已分析 / 待分析”计数。

### 局部精修出现 HTTP 500

1. 刷新页面并重新打开当前任务。
2. 确认源图和 `workspace/jobs/<job-id>/` 仍存在。
3. 检查终端中的服务错误。
4. 运行测试确认环境：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

### GPU/CUDA 没有启用

访问 `/api/health` 或查看页面右上角状态。如果没有 `CUDAExecutionProvider`：

- 检查 NVIDIA 驱动。
- 检查虚拟环境中的 `onnxruntime-gpu`。
- 重新打开终端和服务。
- 即使 GPU 不可用，也可以选择 CPU，只是速度较慢。

### 模型下载失败

在 GUI 设置中填写 HTTP/HTTPS Proxy，或使用 `start_gui.ps1 -Proxy`。模型缓存位于 `.models/`，未完成的下载可以在确认无用后重新下载。

## 15. 数据与备份

| 目录 | 内容 | 是否可删除 |
| --- | --- | --- |
| `input/` | 导入的源素材 | 删除后无法从素材库重新打开；先确认已备份 |
| `output/` | 标准导出缓存 | 可以删除，但需要重新导出 |
| `workspace/jobs/` | 分析任务和人工修改 | 删除后历史与局部修改无法恢复 |
| `workspace/trash/` | 可恢复回收站 | 确认不再恢复后可以清理 |
| `.models/` | AI 模型缓存 | 可以删除，之后会重新下载 |
| `.venv/` | Python 环境 | 可以重建，但删除后工具暂时无法启动 |

如果要迁移整套工作环境，至少备份 `input/`、`workspace/` 和需要保留的外部导出目录。

## 16. 推荐工作习惯

1. 生成端已知帧数时始终传入 `expected_frames`。
2. 先使用默认参数分析，再根据具体问题只调整一个参数。
3. 全局精修从“保守”开始，局部问题优先使用圈选工具。
4. 对比初抠和精修，先判断错误发生在哪个阶段。
5. `review_count > 0` 表示需要检查，不代表处理失败。
6. 导出动画前检查首帧、末帧、极端动作和分离特效。
7. 在游戏项目中优先使用 `frames_aligned`；需要自定义锚点时再使用 `frames_trimmed` 和 manifest。
8. 定期备份 `workspace/`，不要把任务历史当作可随时重建的缓存。
